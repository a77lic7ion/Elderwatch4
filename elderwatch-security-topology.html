Summary

  • All external connections use HTTPS with TLS 1.3. No plaintext HTTP for data in transit.
  • Vercel automatically provisions and renews Let's Encrypt certificates for both custom domains.
  • HSTS is enabled on all Vercel deployments, forcing browsers to use HTTPS.
  • Google Cloud services (Firestore, Auth, FCM) use their own CA (Google Trust Services).
  • No custom certificates or certificate pinning is implemented.
  • Web Push uses the standard VAPID protocol for authentication between server and push service.

Security Findings

Critical

1. Firestore rules are wide open
Every collection (residents, homes, staff, checkins, pushLogs, jobLogs, device_bindings) allows read, write: if true. Any client — including a resident's phone — can read/write ANY document, including staff records, other residents' data, and check-in history for all homes. This is the #1 issue to fix before real residents use the system.
2. No server-side authentication on resident operations
Resident device binding is purely client-side (localStorage/IndexedDB). A technically savvy user could manipulate their elderwatch_device_binding to impersonate another resident. There is no Firebase Auth token or server-side session for resident check-ins — the Firestore client SDK writes directly with no auth context.

Warnings

3. VAPID private key in .env.local
The VAPID private key is stored in .env.local (gitignored) locally and in Vercel environment variables. This is correct practice, but ensure the Vercel env var is restricted to Production only and not exposed in Preview deployments.
4. Firebase service account credentials
service-account.json exists in two locations: the Elderwatch3 working copy and the Elderwatch4 project root. Both are gitignored. Ensure they are never committed. The cron jobs use these credentials via Vercel env vars (FIREBASE_CLIENT_EMAIL, FIREBASE_PRIVATE_KEY).
5. Staff auth uses inMemoryPersistence
Firebase Auth is configured with inMemoryPersistence — the staff session lives only in the browser tab's memory. Closing the tab logs the staff member out. This is good for security but may be inconvenient. The session is also stored in sessionStorage as a backup.
6. No rate limiting on any endpoint
The Vercel serverless functions (daily-reset, reminder-push) have no rate limiting beyond Vercel's built-in DDoS protection. The CRON_SECRET protects manual invocation, but the client-side Firestore writes have no throttling.

Informational

7. TWA origin separation is working
The resident APK (elderwatch-resident.vercel.app) and admin web app (elderwatch3.vercel.app) are on completely separate origins. Chrome's TWA does not share localStorage, sessionStorage, cookies, or service workers between them. This was the root cause of the routing bugs and is now correctly resolved.
8. Web Push uses VAPID correctly
Push subscriptions are authenticated with VAPID keys. The public key is embedded in the client bundle and set as a Vercel env var. The private key is only used server-side in the cron job. Dead subscriptions (404/410 from FCM) are automatically cleaned up.
9. IndexedDB binding storage
Device bindings are stored in IndexedDB as a backup for when TWA clears localStorage on exit. IndexedDB is origin-scoped and persists across app restarts. This is not a security concern but means a factory reset or app data clear is required to fully remove a binding.

Recommended Actions

Before Pilot

  • Lock down Firestore rules: residents can only read/write their own checkin doc; staff can read/write for their home; admin-only for staff/homes collections.
  • Add Firebase Auth for resident operations (anonymous auth or custom tokens tied to device binding).
  • Audit Vercel env var visibility (Production vs Preview).
  • Verify CRON_SECRET is not guessable.

Nice to Have

  • Add certificate pinning for the TWA (Android Network Security Config).
  • Implement Content Security Policy headers.
  • Add rate limiting on serverless functions.
  • Set up Firebase App Check to prevent unauthorized API calls.
  • Add audit logging for admin actions.
